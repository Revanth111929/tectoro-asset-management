WHY THIS HAPPENED
════════════════════════════════════════════════════════════════════════════════

Original Intention:
  - Block old Flask blueprint routes (/assets/<id>)
  - Prevent conflicts between Flask and React routing

What Went Wrong:
  - Condition was too broad (path.startswith('assets'))
  - Blocked ALL paths starting with "assets"
  - Didn't account for React Router needs

Lesson Learned:
  - Flask should only block actual API endpoints
  - Let React Router handle ALL frontend routes
  - Test direct URL access, not just navigation
  - Follow standard Flask + React SPA patterns

════════════════════════════════════════════════════════════════════════════════
TECHNICAL EXPLANATION
════════════════════════════════════════════════════════════════════════════════

Flask + React SPA Routing Pattern:

1. User visits: /assets?status=Available
2. Flask receives request
3. Flask checks: Is it /api/*? No
4. Flask serves: index.html (React app)
5. Browser loads React app
6. React Router reads URL: /assets?status=Available
7. React Router renders: <AssetList /> component
8. Component reads query param and filters assets

Key Point: Flask serves HTML, React handles routing logic
